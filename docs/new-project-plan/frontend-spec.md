# Bessonniy Oracle: Спецификация фронтенда

Документ описывает требования к клиентским приложениям (Flutter: Android/iOS/Web) для реализации UX из user-flow.

## 1. Архитектура
- Flutter (Dart).
- Управление состоянием: Riverpod (целевой выбор); допускается Provider на первом шаге, но с планом миграции.
- Навигация: `go_router` или стандартный Navigator 2.0, глубокие ссылки опционально.
- Слои: presentation (виджеты/экраны) → state (notifiers/providers) → data (репозитории) → api/http.
- DI: Riverpod providers.
- Локализация: `flutter_localizations`, минимум ru, en.

## 2. Экраны и состояние
- Сплэш/загрузка: показывает логотип, статус и ошибки инициализации (нет сети/бэкенда).
- Главный экран (чат):
  - Имя активной персоны над смайликом.
  - Смайлик с эмоциями и статусами (нейтрал/думает/говорит/ошибка/оффлайн).
  - История сообщений (ленивая подгрузка вверх, кнопка “к последнему”).
  - Поле ввода текста, кнопка Отправить/Отмена (во время запроса).
  - Голосовой ввод: кнопка/иконка записи, индикаторы слушаю/распознаю/ошибка.
  - Статусы: оффлайн, таймаут, лимит длины — показывать подсказки и не терять ввод (черновик).
- Боковая шторка (чаты): список чатов, создание нового (выбор персоны), удаление с подтверждением, пустое состояние.
- Экран настроек: список персон, добавление/редактирование/удаление, пустое состояние.
- Экран создания/редактирования персоны: имя, системный промт, список правил (CRUD), пустое состояние правил, подтверждение удаления.

## 3. Ввод и ограничения
- Текст: ограничение длины (конфигурируемое, например 4000 символов); подсказка при превышении.
- Аудио: ограничение длительности/размера (например до 20 сек, 1 МБ); при превышении — явное сообщение.
- Кнопка Отправить превращается в Отмена на время запроса/ответа; остановка TTS при отмене.

## 4. Работа с сетью
- HTTP-клиент: Dio (рекомендуется) с интерцепторами (base URL, headers, x-request-id).
- Ретраи для GET (чтение) с небольшим backoff; POST без авто-ретраев, только явная кнопка “Повторить”.
- Обработка кодов: 400 (валидация), 401/403 (показать экран входа/алерт), 429 (показать лимит и кнопку “Повторить позже”), 5xx (общая ошибка, предложение попробовать ещё).
- Оффлайн-режим: показывать статус, сохранять черновик сообщения, запрет отправки до восстановления.

## 5. Голосовые функции
- STT: использовать нативный `speech_to_text` (mobile) и Web Speech API (web); при ошибке — фолбек на текстовый ввод.
- TTS (MVP): системный — `flutter_tts` (mobile) и Web Speech API (web); без облачных провайдеров.
- Выбор голоса: список системных голосов устройства/браузера; хранить выбранный id в настройках; предпрослушивание перед сохранением.
- Горячие слова/команды (минимум): “Оракл/Афина/Фортуна, новый чат”, “новое правило <текст>”, “смени персону на <имя>”, “стоп/отмена”.
- Визуализация состояния записи/воспроизведения (индикаторы, прогресс/пульсация).

## 6. Работа с API
- Базовые эндпоинты см. `backend-spec.md` (personas, rules, chats, messages, health, voice).
- Формат сообщений: role (user|assistant|system), content, timestamps.
- Пагинация истории: `cursor`/`limit`, подгрузка вверх.
- Обновление состояния после операций: invalidate cache для персон/чатов/правил.

## 7. Доступность и UX
- Контраст и масштаб шрифта, поддержка экранных ридеров.
- Клавиатурная навигация (web).
- Подписи/субтитры для TTS-ответов (текст всегда доступен).
- Пустые состояния с CTA на ключевых экранах.

## 8. Безопасность
- Не хранить ключи API в приложении; всё через бэкенд.
- Минимизировать логирование содержимого сообщений на клиенте; crash logs без текста пользователя.
- Проверять размер/тип файлов аудио перед отправкой.

## 9. Конфигурация
- ENV через `--dart-define`: `API_BASE_URL`, `BUILD_ENV`, лимиты (TEXT_MAX_LEN, AUDIO_MAX_SEC).
- Фича-флаги: включение голосовых функций и веб-voice отдельных.

## 10. Тестирование
- Unit: провайдеры/нотификаторы, валидации, мапперы моделей.
- Widget-тесты: экраны чата, шторки, настроек, формы персоны, пустые состояния, ошибки/оффлайн.
- Интеграционные: сетевые вызовы с моками, ретраи, обработка кодов 4xx/5xx.
- Снапшоты недопустимы для динамических областей (история), но возможны для статичных пустых состояний.

## 11. Производительность
- Ленивая подгрузка истории, список сообщений с рендером по ключу.
- Дебаунс ввода перед отправкой голосовых команд (распознавание).
- Кеширование списков персон/чатов в памяти с быстрой инвалидацией.

## 12. Локализация и время
- Все пользовательские сообщения и ошибки через локализованные ресурсы.
- Форматы дат/времени — локаль устройства.
