# Jira: Кросс-платформенный голосовой ввод (STT) и воспроизведение TTS

## Навигация

- `problem-summary.md` — текущее состояние, первопричина, ограничения и целевое решение
- `backend-spec.md` — спецификация backend-части для STT/TTS-совместимости
- `frontend-spec.md` — спецификация frontend-части (web + desktop + mobile)
- `tasks.md` — поэтапный план реализации, задачи и подзадачи с чекбоксами

## Кратко о проблеме

- В web на Raspberry микрофон разрешен, но Web Speech API возвращает `error: network`.
- В desktop Linux текущая реализация не обеспечивает воспроизведение серверного `audioUrl` (идет fallback на локальный TTS).
- Поведение зависит от браузера/платформы, а целевое требование — единый стабильный сценарий "нажал микрофон -> отправил текст -> получил голосовой ответ".

## Цель

- Сделать голосовой контур независимым от браузера и платформы:
  - STT через backend (основной путь),
  - TTS через серверный `audioUrl` (основной путь),
  - локальные возможности браузера/ОС только как fallback.

## Критерии готовности

- Микрофон работает на Raspberry в браузере без Web Speech API-зависимости.
- Микрофон и озвучка работают одинаково в Chrome/Chromium/Firefox и Linux desktop.
- В UI есть понятный индикатор: какой режим используется (server/local/fallback).
- Логи позволяют отладить цепочку `mic -> stt -> llm -> tts -> playback`.
